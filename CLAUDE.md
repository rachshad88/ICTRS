# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

ITRS is the request system of the LGU Solano IT office: clients file IT, multimedia (event coverage), digital
media and print requests; staff work them; admins assign, prioritise and report. `frontend-ts/` is a React 18 +
Vite 7 SPA, `backend-ts/` an Express + MongoDB API. **This machine is the production server**: the backend on
:3000 and MongoDB hold real data.

Deeper docs: `SYSTEM_ARCHITECTURE.md` (roles, data model, lifecycle, sockets), `deploy/README.md` (deploy,
nginx, backups, MongoDB access), `deploy/RATING_DB.md` (rating system link). Where they disagree with the code,
the code wins; known stale spots are noted below.

## Commands

There is no test suite and no linter. The checks are the TypeScript compilers, and for UI work a real browser.

```bash
# Frontend: type-check, then publish (nginx serves the built files, not a dev server)
cd frontend-ts && npx tsc --noEmit -p .
./deploy/deploy-frontend.sh            # from the repo root: tsc, vite build, brotli/gzip, rsync to /var/www/itrs

# Backend: build and reload the PM2 cluster without downtime
cd backend-ts && npm run build && sudo pm2 reload backend
sudo pm2 logs backend

# nginx config changes (edit the repo copies in deploy/, never /etc/nginx directly)
sudo ./deploy/install-nginx.sh
```

- `npm run dev` in `frontend-ts` proxies `/api` and `/socket.io` to `localhost:3000`, i.e. the **live** backend.
  For UI testing, build to a scratch dir and serve it with
  `npx vite preview --outDir <dir> --port 5199 --host 127.0.0.1`, and mock `/api` (Playwright `page.route`)
  instead of signing in or writing test data to the live API.
- Playwright's bundled Chromium is in `~/.cache/ms-playwright/chromium-1148/` (use `playwright-core` with
  `executablePath`). It cannot play H.264. The built page's CSP has no `unsafe-eval`, so `page.waitForFunction`
  fails; poll with locators instead.

## Repo and server conventions

- The repo is owned by `user`; Claude runs as root. Run git as `sudo -u user git ...` (root gets "dubious
  ownership", and the GitHub SSH key belongs to `user`), and `chown user:user` files created or edited as root.
  Install npm packages with `sudo -u user -H npm install`.
- After finishing a frontend change, deploy it with `./deploy/deploy-frontend.sh`, then check the new code is in
  `/var/www/itrs/assets` and `https://localhost/` returns 200. Commit and push only when asked.
- MongoDB (4.4) runs in **Docker**, so `ufw` does not control port 27017. Remote access is allowed by
  `deploy/itrs-mongo-firewall.sh` (`ALLOWED` list, installed to `/usr/local/sbin/` and run by
  `itrs-mongo-firewall.service`). `/etc/mongod.conf` is not the config the running database uses.
- nginx's `mime.types` has no `.mjs`: anything loaded as a module or worker must be emitted as `.js` (for
  example `import X from '...?worker'`).

## Backend architecture (`backend-ts/src`)

- `index.ts` wires everything: helmet, `trust proxy` = loopback, `query parser: simple` (so `?a[$ne]=x` stays a
  literal key and can't become a MongoDB operator), sessions in MongoDB (`connect-mongo`), Socket.IO
  authenticated from the same session cookie, routes under `/api`, and timezone forced to `Asia/Manila`.
- **PM2 cluster** (`ecosystem.config.js`): one process per core minus two (10 on this server). Processes share
  sockets, the login throttle and caches through Redis (`@socket.io/redis-adapter`); without Redis, live events
  only reach users on the same process. Timed jobs (rating sync, overdue alerts) run only where
  `NODE_APP_INSTANCE === '0'`. `SYSTEM_ARCHITECTURE.md` still says one instance.
- **Auth is enforced on the server**: `middleware/auth.ts` re-reads the user on every request (must exist, be
  approved and active, and match `session_version`; one session per user, so `SESSION_REPLACED`). Default
  password → `403 PASSWORD_CHANGE_REQUIRED` except on `/api/auth/*`. Role guards (`isAdmin`, `isItAdmin`,
  `isMultimediaAdmin`, ...) sit on each route; frontend route guards only decide what to show.
- **Four request types, two code paths**: IT requests live in `routes/requests.ts`; multimedia, digital media
  and print are all generated by `routes/multimediaFactory.ts` with a different prefix, collection and fields.
  A change to media request behaviour usually belongs in the factory. Codes are `IT-/MM-/DM-/PM-<year>-<seq>`
  from the `counters` collection.
- Bodies are validated with zod (`middleware/validation.ts`, `validate.ts`). Uploads go through multer with
  extension and size checks in `utils/fileValidation.ts` (10 MB per file) into `backend-ts/uploads/`; the
  frontend's `FileDrop` mirrors those rules. A new upload route needs its own nginx location
  (`deploy/nginx-itrs-api.conf`), or it gets the 1 MB body limit.
- `utils/notify.ts` writes `notifications` rows and emits to Socket.IO rooms (`user_<id>`, `admins`,
  `super_admins`, `technicians`, `multimedia_staff`, `clients`).
- **Rating (CSF) link**, `utils/ratingSync.ts`: completed requests are copied into
  `itrs_rating.requests` as `{request_code, status: 'DONE'}`; the separate CSF app sets `RATED`; ITRS polls
  every 15 s and marks its own request `RATED`. ITRS only inserts there. `deploy/RATING_DB.md` is current; the
  rating section of `SYSTEM_ARCHITECTURE.md` (`request_status`, overwrite every 10 min) is outdated.
- Unauthenticated routes: `/api/csf` (needs `X-CSF-Key` = `CSF_API_KEY`; closed when unset), `/api/live`
  (wall display, limited to `LIVE_ALLOWED_CIDRS`), `/api/health`.

## Frontend architecture (`frontend-ts/src`)

- `routes.ts` lists every page with the roles allowed to open it. Pages are lazy-loaded and prefetched (after
  login, during curtain transitions, when idle); the landing page stays in the main bundle behind the boot
  loader in `index.html`.
- Data: `services/api.ts` (axios at `/api`; its interceptor redirects on `SESSION_EXPIRED`/`SESSION_REPLACED`
  and sends `PASSWORD_CHANGE_REQUIRED` to `/profile`) and TanStack Query (`services/queryClient.ts`).
  `contexts/AuthContext` holds the user; `contexts/NotificationContext` owns the socket, toasts and bell panel.
- **CSP**: `vite.config.ts` injects a meta CSP at build time (`script-src 'self'` plus hashes of inline
  scripts, `img-src 'self' data: blob:`, `media-src 'self' blob:`, `font-src 'self'`, `object-src 'none'`).
  Inline event handlers in `index.html` are blocked, and so are `data:` fonts and third-party origins. nginx
  adds `frame-ancestors`/`nosniff` headers.
- Caching: built files are content-hashed in `/assets/` and cached for a year (`immutable`). Fonts in
  `public/fonts/` are not hashed: a changed font needs a new file name. Large media (the landing page's guide
  video, `src/assets/`) is imported so it gets a hashed name.
- **Modals**: markup is `.modal > .modal-content` with `.modal-header`/`.modal-close`. `useModalEscape` in
  `App.tsx` presses the `[data-modal-dismiss]` button of the topmost `.modal` on Escape. Dialogs are portalled
  into `.app-main`; at ≤640px they become bottom sheets.
- Lists page client-side with `components/Pagination.tsx` at 10 per page (pass `label` when a page has more
  than one set of page controls).
- Styles are plain CSS in `src/styles/` (tokens in `tokens.css`); the public pages (`landing.css`, `guide.css`)
  have their own `--lp-*`/`--gd-*` palettes. Motion uses framer-motion with eases from `lib/motion.ts`, and
  respects `useReducedMotion`.
- The mobile layout switches at 768px (`MOBILE_QUERY` in `App.tsx`): top bar plus bottom nav, and
  notifications in a bottom sheet.
